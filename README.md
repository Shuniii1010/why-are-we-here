# why-are-we-here
Assignment 1 — "Why are we here?" 

As a student on the research pathway and a visual communication design student, I often ask myself why I need to learn programming when AI systems can already generate working code from a sentence. Since GPT-6 was released, this question has felt even more urgent. If I can describe what I want in English and receive a functioning program, why should I spend time learning programming myself?

At first, I thought programming might be useful mainly because it could help me analyse research data. An AI assistant such as Codex can generate a complete data-analysis script in a few seconds. However, this does not mean that I can completely depend on it. I still need to understand whether the code answers my research question, whether the data has been processed correctly, and how to change the code when my requirements are not expressed precisely enough. Writing code and understanding code are not the same skill.

I experienced this recently while using Overleaf to create my CV. I copied a CV template from GitHub and asked Codex to replace the original information with my own. The first version was mostly usable. Later, I wanted to add more experience, so I tried to edit the document directly in Overleaf. However, I knew almost nothing about LaTeX. I did not understand why certain symbols, such as curly brackets, were necessary or what role they played in the document. After I changed the file manually, it stopped compiling and the screen filled with error messages.

At that moment, I realised that having an AI agent does not mean that I can simply stop thinking. Codex had helped me produce the first version, but it could not completely remove my responsibility as the user. I had to compare the broken version with the original code and gradually guess what the different symbols and structures meant. It took me an entire afternoon to fix the CV. Although this was frustrating, solving the problem gave me a strong sense of achievement. I began to understand that even a small amount of programming knowledge would make my future work much more efficient. Instead of repeatedly asking AI to repair a problem that I did not understand, I could identify the problem and give more precise instructions.

This experience also connects to programming as a creative medium. I have always been curious about the tools through which people create things. When I first learned Photoshop and Adobe Illustrator, I spent long periods sitting in front of the computer doing small exercises. I worked slowly and often made mistakes, but I continued because I enjoyed the feeling of making something myself. The purpose was not always to produce an impressive final image. Sometimes the satisfaction came from overcoming a difficult step.

Since AI image generators became widely available, this feeling has become more complicated. With a few prompts, AI can produce images that might previously have taken me several hours to make. This is convenient, but it can also feel discouraging, especially for students of visual communication design. When a visual result can be generated almost instantly, I sometimes become less willing to spend time experimenting with composition, colour and form. The speed of the result can replace the slower satisfaction of learning.

This is why Dylan Beattie’s The Art of Code was meaningful to me. The talk presents programming not only as a technical process, but also as a form of expression. Code can generate images, music, patterns and unexpected behaviours. It can be playful, personal and even useless in a practical sense. This changed the way I think about programming. I do not have to learn it only to become a professional software developer. I can also learn it as another material for creative work.

I originally enrolled in this course partly because I felt anxious about “vibe coding”. Many people on social media were sharing projects created with AI, while I had not yet tried to make anything similar. I worried that I was falling behind. During the first workshop, I struggled to follow the process. After returning home, I spent extra time repeating the steps until I finally understood how they worked. The difficulty was tiring, but it also produced a kind of excitement. I felt that I had learned something rather than simply received an answer.

Therefore, I do not think learning programming is valuable because I must compete with AI by writing code faster than it can. Instead, programming can help me understand the medium I am working with, evaluate AI-generated results, correct failures and make more intentional creative decisions. I want to learn how to collaborate with AI without becoming completely dependent on it. Whether I make a useful research tool, a small program with no obvious purpose, or a piece of coding art, I want to recover the satisfaction of creating through effort, experimentation and persistence.

Perhaps the value of programming is not only in the quality of the final product. It is also in what happens during the process: the problems I encounter, the decisions I make and the things I learn while solving them. Even if AI continues to become more capable, I still want to understand enough to remain an active participant in my own work.
