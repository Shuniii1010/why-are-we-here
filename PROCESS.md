# PROCESS.md

## How I Used AI

During the process of writing this essay, I used Codex for understanding the video, analysing the assignment requirements, brainstorming, planning the essay structure, drafting, editing, and receiving guidance on GitHub and Markdown. 

First, I used Codex to help me understand the assignment. It translated the instructions into Chinese and explained the main question that the essay should address: why should artists or designers still learn programming when AI systems are increasingly able to generate code automatically? Through this process, I realised that the tutor was not looking for a general argument that “programming is useful” or that “AI cannot replace humans”. The essay needed to answer what programming means to me personally and how it relates to my own practice.

I also used Codex to help me understand Dylan Beattie’s talk *The Art of Code*. The talk made me realise that programming is not only a way to solve technical problems, but also a medium for creative expression.

After that, I shared my original draft with Codex, including my own experiences:

- As a research pathway student, I may need programming to analyse research data;
- Codex once helped me create a CV using LaTeX and Overleaf;
- When I first learned Photoshop and Illustrator, I enjoyed practising and solving problems by myself;
- During the first workshop, I initially struggled to follow the process, but I repeated the steps at home and eventually understood them. This gave me a sense of achievement.

Based on these experiences, Codex helped me brainstorm the main argument and supporting points of the essay. The original structure was quite scattered, so I reorganised it into three connected arguments:

1. AI can write code, but people still need to read, judge and modify it;
2. Understanding code and the medium is necessary for keeping personal judgement and authorship;
3. Thinking, practising and learning through difficulty can help maintain creative enthusiasm and a sense of achievement.

Codex also helped me draft the English essay. I then asked it to make several revisions, including shortening the essay, changing the opening, improving the connections between paragraphs, correcting grammar and making the language sound more natural.

In addition, I used Codex for practical guidance with GitHub, Markdown and Git. It explained how to add images and links to a README file, how to create an `assets` folder, and how to use commands such as `pull`, `push`, `commit`, `branch` and `merge`. Later, my local repository and GitHub repository developed conflicting histories. Codex helped me understand the error messages, identify the relevant commit, create a backup branch and restore the repository.

## What I Kept from the AI

I kept the essay structure suggested by Codex because my original draft were quite scattered and lacked a clear logical connection. Codex helped me organise these separate ideas and connect them into a coherent structure for the essay.

I also kept the central argument that Codex helped me formulate:

> I am learning programming in order to understand and control the medium I am using. AI can help me generate code, but only by understanding the basic principles can I judge whether the code meets my needs, correct errors and genuinely participate in the creative process.

I kept this argument because it accurately expresses my own position and connects research, design and creative practice. 



## What I Rejected and Changed

I rejected the first draft that Codex generated directly from my original draft because I felt that many of the expressions were repetitive and unnecessarily wordy. The draft was also over the required word limit.

When a conflict developed between my local repository and my GitHub repository, I asked Codex for help. Its initial suggestion was to merge the commits from the local and online repositories and then delete the unnecessary submodules. This approach might have been technically possible, but my repository already contained several branches, merges and files that did not belong to the assignment. Continuing to merge everything and then dealing with the submodules could have made the repository history even more complicated. It also increased the risk of deleting the wrong files or uploading the unwanted files again.

Therefore, I rejected this suggestion. I decided that it would be simpler to return to the commit before the problem started. I found the commit where I had first uploaded the Overleaf screenshot, created a backup branch and then reset the repository to that earlier point.

I also rejected Codex’s initial opening for the essay:

> As a research pathway student and a visual communication design student, I often wonder why I need to learn programming when AI systems can already generate working code from a sentence.

I felt that this opening was too direct and slightly awkward. It sounded like a mechanical introduction of my identity and did not immediately reach the central question of the essay.

## How I Completed the Final Version

After completing the essay and the GitHub work, I asked Codex to review our previous conversation and summarise everything it had helped me with. I then used that summary to create the first draft of this `PROCESS.md` file.

I did not copy the draft without changes. I manually removed some technical details from the main essay to avoid repeating the same information in both files. I also added more explanation about why I rejected certain AI suggestions, especially the suggestion to merge the conflicting repository histories and delete the unnecessary submodules.

Finally, I used Codex again to improve the wording and make the structure of this document clearer. 

This process made me realise that AI can help organise and express ideas, but it cannot automatically know which words genuinely represent my point of view. Deciding whether a plausible-sounding paragraph actually belongs to my argument is still my responsibility. This reflects the main idea of my essay: AI can assist with creative work, but people still need to understand, judge and control the process.
